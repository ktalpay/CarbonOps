# Synthetic Demo Scenario

## Scenario Purpose

This scenario describes a possible future public-safe demo for CarbonOps. It uses fictional pipeline metadata and does not represent a real company, customer, production system, endpoint, or metric.

## Synthetic Input Assumptions

A future demo could use synthetic fields such as:

- Pipeline name: `example-build`
- Region: `gb_london`
- Duration: `30m`
- Policy mode: `delay`
- Data source: placeholder or documented public data source
- Output type: estimate or demonstration

These fields are illustrative and should not be treated as production telemetry.

## What A Future Adapter Would Need

A future adapter would need:

- Documented carbon-intensity data source.
- Region mapping.
- Time-window handling.
- Missing or stale data behavior.
- Methodology notes.
- Test coverage.

## What The Current Repo Does Not Yet Do

The current repository does not yet:

- Query real carbon-intensity data.
- Calculate CO2e.
- Make real scheduling decisions.
- Produce methodology-backed reports.
- Demonstrate operational maturity.
- Prove verified emissions reduction.

## Safety Notes

Do not include:

- Real company data.
- Customer data.
- Production endpoints.
- Internal service names.
- Credentials or secrets.
- Revenue or transaction metrics.
- Claims of public adoption, production usage, commercial impact, verified emissions reduction, or external recognition.
